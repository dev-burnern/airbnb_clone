# Git 커밋 및 PR 워크플로우

각 기능 구현이 완료되면 아래 단계를 수행합니다.

## 1. 브랜치 생성
// turbo
- 기능에 맞는 브랜치 생성 (예: `feature/기능명`, `fix/수정명`, `chore/작업명`)
```bash
git checkout -b <브랜치타입>/<기능명>
```

## 2. 변경 사항 스테이징
// turbo
```bash
git add <변경된 파일들>
```

## 3. 깃모지 + 한글 커밋
커밋 메시지 형식:
```
<깃모지> <타입>(<스코프>): <한글 설명>
```

### 깃모지 가이드
- ✨ (`:sparkles:`) - 새 기능 추가
- 🐛 (`:bug:`) - 버그 수정
- 🔧 (`:wrench:`) - 설정 파일 수정
- 📝 (`:memo:`) - 문서 수정
- 💄 (`:lipstick:`) - UI/스타일 수정
- ♻️ (`:recycle:`) - 코드 리팩토링
- 🔥 (`:fire:`) - 코드/파일 삭제
- 🚀 (`:rocket:`) - 배포 관련
- ✅ (`:white_check_mark:`) - 테스트 추가/수정
- 🔒 (`:lock:`) - 보안 관련
- ⬆️ (`:arrow_up:`) - 의존성 업그레이드
- 🎨 (`:art:`) - 코드 구조/포맷 개선

### 타입 가이드
- `feat` - 새 기능
- `fix` - 버그 수정
- `chore` - 기타 작업
- `docs` - 문서
- `style` - 스타일
- `refactor` - 리팩토링
- `test` - 테스트

## 4. 원격 저장소에 푸쉬
```bash
git push origin <브랜치명>
```

## 5. PR 타이틀 및 코멘트 작성
복붙 가능하게 마크다운 형식으로 제공:

### PR 타이틀 형식
```
<깃모지> [<스코프>] <한글 설명>
```

### PR 코멘트 템플릿
```markdown
## 📝 변경 사항

- 변경 내용 1
- 변경 내용 2

## 🤔 변경 이유

변경하게 된 배경 및 이유 설명

## ✅ 체크리스트

- [ ] 코드 테스트 완료
- [ ] 빌드 확인
- [ ] 관련 문서 업데이트 (필요시)
```
